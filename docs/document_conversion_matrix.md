# מטריצת המרת מסמכים — מה נתמך בכל פורמט

מסמך זה הוא **חוזה ההמרה** של אוצריא: לכל אלמנט במסמך המקור, איזה HTML
הממיר מייצר, ובאילו פורמטים.

עודכן: 2026-08-17. כל שורה אומתה מול הקוד ומול הרצת המרה על מסמך בדיקה
אמיתי בכל אחד מהפורמטים.

## מקרא הפורמטים

| עמודה | פורמטים |
|---|---|
| **OOXML** | ‎.docx‎, ‎.docm‎, ‎.dotx‎, ‎.dotm‎, וכן ‎.xml‎ בדיאלקט Flat OPC |
| **XML03** | ‎.xml‎ בדיאלקט WordprocessingML 2003 (`w:wordDocument`) |
| **ODT** | ‎.odt‎ |
| **RTF** | ‎.rtf‎ |
| **DOC** | ‎.doc‎, ‎.dot‎, ו-‎.wbk‎ שתוכנו Word בינארי |

‎.wbk‎ מנותב לפי תוכנו: חבילת OOXML → עמודת OOXML, בינארי → עמודת DOC.

מקרא: ✅ נתמך · ⚠️ נתמך חלקית (ראו הערה) · ❌ אינו נתמך · — אין לו ייצוג
בפורמט.

### כלל היישור

יישור שמאל/ימין נכתב רק כשהוא **חד-משמעי**:

| מצב | התנהגות |
|---|---|
| `center` | תמיד נכתב |
| ערך פיזי (`left`/`right`) ב-OOXML/XML03/ODT | נכתב — הפורמטים האלה כותבים יישור רק כשהוא מפורש |
| ערך פיזי ב-RTF, פסקה LTR | `\qr` נכתב; `\ql` מדולג — Word כותב אותו כמעט בכל פסקה, ולכן הוא ברירת מחדל ולא הצהרה |
| ערך לוגי (`start`/`end`, `\ql`/`\qr`) בפסקה LTR | נפתר ונכתב |
| ערך לוגי בפסקה **RTL** | **מדולג** |

**למה:** מפיקי המסמכים חלוקים בפירוש היישור הלוגי בפסקה RTL. אותו מסמך
נשמר ב-Word כ-`w:jc="end"` בלי `w:bidi` (כלומר ימין), ב-LibreOffice כ-
`fo:text-align="end"` עם `rl-tb` (שלפי תקן ODF הוא שמאל), וב-RTF כ-`\ql`
בתוך `\rtlpar`. Word עצמו כותב יישור מפורש כמעט בכל פסקה, ולכן הכרעה
שגויה אינה משפיעה על פסקה בודדת אלא **מיישרת ספר עברי שלם לצד ההפוך**.
בהיעדר סימון, הקורא מיישר לפי כיוון הטקסט — וזו התוצאה הנכונה כמעט תמיד.

## מגבלות רוחביות

| נושא | התנהגות |
|---|---|
| משאב חיצוני | **לעולם אינו נטען מהרשת.** יחס שנתיבו מפנה לחבילה עצמה (`ooxWord://…`) נקרא מתוכה; יחס ל-`http://` מדולג |
| מסמך מוצפן | `EncryptedDocumentException` — לא "קובץ פגום" |
| מסמך שגופו אינו קריא | `CorruptedDocumentException` בכל הפורמטים. מסמך **ריק אך תקין** מחזיר כותרת בלבד ואינו כשל |
| ערך צבע/יישור מתוך המסמך | מסונן מול תחביר CSS לפני שהוא נכנס ל-`style`; ערך שאינו תקין מדולג ואינו מוצג |
| רקע תא לבן | מדולג בכל הפורמטים — הוא ברירת המחדל ושובר את המצב הכהה |
| קובץ פגום בסריקה | הכשל נרשם והסריקה ממשיכה לקובץ הבא |
| מאקרו (‎.docm‎/‎.dotm‎) | אינו מורץ. הממיר קורא תוכן בלבד |
| תקרות פריסה | חבילת ZIP נבדקת מול מספר רשומות, גודל פרוס ויחס דחיסה — לפני ואחרי הפריסה |

## נספח: מה נבדק בפועל

מסמך בדיקה יחיד, שנשמר ב-11 קבצים בכל הפורמטים, הומר בשרשרת המלאה
(‎`convertDocumentFileSync`‎) ונמדד מול כל שורה בטבלאות שלמעלה.

ששת קובצי משפחת OOXML (‎.docx‎/‎.docm‎/‎.dotx‎/‎.dotm‎ ושני קובצי Flat OPC)
מייצרים פלט **זהה** — 1,150 שורות ו-347,142 תווים עבריים בכל אחד. זהו
קריטריון השקילות בין הפורמטים.

מדדים שכל 11 הקבצים מסכימים עליהם: **631 הערות שוליים**, שלוש טבלאות,
ואפס יישורי-שמאל מזויפים. תיבות הטקסט: 8 בכל פורמט שמצהיר עליהן.

שלושה פערים שנמצאו הם של **מסמך המקור** ולא של הממיר, ומתועדים כאן כדי
שלא ייחקרו שוב:

1. כל סוגי הרשימות במסמך הבדיקה מצביעים על אותה הגדרה אחת (`numId=1`),
   ולכן כולם מוצגים כמספור עשרוני רץ. הממירים תומכים בכל הפורמטים —
   הבדיקות ביחידה מקבעות זאת לכל פורמט בנפרד.
2. פסקת ה"יישור לשמאל" איבדה את היישור שלה בשמירה, ואין בקובץ שום פסקה
   מיושרת-שמאל.
3. גרסת ה-‎.docx‎ מפצלת פסקאות שגרסת ה-ODT ו-WordML 2003 שומרות שלמות
   (1,150 שורות מול 763). אין הבדל בתוכן — מספר התווים העבריים זהה.
